# Waiting Spark Portal

An SPA responsible for onboarding, configuration, subscription, etc.

## Stack

- React (latest version) with TypeScript (`strict` mode enabled)
- Vite
- React Router for routing
- `@supabase/supabase-js` for authentication (email/password or Google)
- [MUI](https://mui.com/) components

## Rules

- Use TypeScript for all code (`.ts` / `.tsx`); avoid `any`, type API request and response shapes
- Page access requires user authentication (using Supabase), except for the public pages listed under Routes
- Always look for an existing MUI component. Avoid building UI components from scratch
- Support Light, Dark, and Auto (follow system) color modes
- Define the theme (palette, typography, spacing) in a single MUI theme module, using CSS variables, so theme settings (especially colors) can be changed in one place
- Follow MUI guidelines regarding themes, spacing, fonts
- Use `WaitSpark.Api`. Group API requests in an `Api` class (`src/api/`)
  - Send the Supabase access token as `Authorization: Bearer <token>` on every request
  - On a 401 response, sign out and redirect to `/signin`
- Store parameters in a `.env` file (added to `.gitignore`); commit a `.env.example` with the same keys and no values. Vite only exposes variables prefixed with `VITE_`:
  - `VITE_API_BASE_URL`
  - `VITE_SUPABASE_URL`
  - `VITE_SUPABASE_PUBLISHABLE_KEY` (publishable key only, never a secret key)

## Project Layout

```
WaitSpark.UI.Portal/
├── public/                  Static assets served as-is (favicon, logo)
├── src/
│   ├── main.tsx             Entry point: renders <App /> with providers
│   ├── App.tsx              Router setup and top-level layout
│   ├── vite-env.d.ts        Vite and `import.meta.env` typings (declare VITE_* vars here)
│   ├── api/                 `Api` class and request/response types
│   ├── auth/                Supabase client, AuthProvider/useAuth, ProtectedRoute
│   ├── components/          Reusable UI components shared across pages
│   ├── hooks/               Reusable custom hooks
│   ├── layouts/             Page shells (e.g. PublicLayout, AppLayout with navigation)
│   ├── pages/               One folder per route, holding the page and its private components
│   │   ├── auth/            SignIn, SignUp, Otp
│   │   ├── onboarding/      Website, Progress, Completed
│   │   └── dashboard/
│   ├── theme/               MUI theme, color modes (Light/Dark/Auto), global CSS variables
│   ├── types/               Shared domain types
│   └── utils/               Pure helper functions
├── .env / .env.example
├── index.html               Vite HTML entry
├── package.json
├── tsconfig.json            (plus tsconfig.app.json / tsconfig.node.json as generated by Vite)
├── vite.config.ts
└── eslint.config.js
```

Conventions:

- One component per file, named in PascalCase, matching the file name (`SignInPage.tsx`)
- Keep page-specific components next to their page; move them to `components/` only when shared
- Pages contain no direct `fetch` or Supabase calls: use `api/` and `auth/`
- Use the `@/` path alias for `src/` (configure in `tsconfig` and `vite.config.ts`)
- Tests live beside the code as `*.test.ts(x)`

## Routes

Public pages:

- /signin
- /signup
- /otp
- /terms (also open to signed-in users)
- /privacy (also open to signed-in users)

Pages requiring authentication:

- /onboarding/start
- /onboarding/progress
- /onboarding/completed
- /dashboard

All other pages require user authentication.
